**`main` is production.** A merge to `main` deploys automatically (see Deployment).

## Data
- **Products + gallery**: Firestore collection `materials`, with images in Firebase Storage (`uploads/<type>/...`). They're read at runtime through `GET /api/storage/all` and `GET /api/storage/type/:type`, and edited through the admin dashboard.
- **Hidden products**: `hidden: true` on a `materials` doc (set by the admin panel's eye button, `PUT /api/storage/product/:id/visibility`). The public endpoints leave hidden docs out; the admin panel lists everything via `GET /api/storage/admin/all`. A product must be hidden before `DELETE /api/storage/product/:id` accepts it (409 otherwise; gallery photos delete directly). The website's product page for a newly hidden product redirects visitors to the products list (runtime check) and disappears from the build/sitemap at the next client-next deploy.
- **Uploads** (`server/src/routes/storage.route.js`): JPG/PNG/WebP only, max 10 MB each, 15 per request; file names are sanitized. When a product's photo is replaced or a finish removed, the old file is deleted from Storage.
- **Small photo copies (thumbs, 2026-11-07)**: every uploaded stone/gallery photo also gets a 640 px WebP copy (sharp, q72) at `uploads/<type>/thumbs/`, saved as `thumb` next to `link` in the finish; it is deleted with its photo. The website uses `thumb || link` in product cards, the home featured slider and the gallery grid, and a srcset on the product page's main photo. Older photos: Products page → "Create small photos" (ADMIN, `POST /api/storage/admin/thumbs`, 15 per call, safe to repeat; the panel only shows it while some photo has no copy), then Publish. Originals are never changed.
- **News** (managed in the admin panel since phase 1; the website reads it at build time):
  - **Storage:** Firestore collection `news` (via `col('news')`). Each article has:
    - `title` / `content` / `excerpt` as `{en, ar}`
    - `year` and `month`
    - `author`, `thumbnail`, `images[{src,alt}]`
    - `slug` (fixed after creation)
    - `pinned` (only one article at a time), `hidden`
  - **API:** public `GET /api/news` returns the visible articles, pinned first, then newest. The admin endpoints live under `/api/news/admin/*` and are limited to **ADMIN/SUPER_ADMIN**; moderators can't use them.
  - **Deleting:** an article must be hidden first, and its uploaded photos are deleted with it. Photos are uploaded to `uploads/News/`.
  - **Allowed photos:** only links to our bucket, or the website's existing `/Assets/Media/...` paths.
  - **One-time import:** `POST /api/news/admin/import` copies the 7 articles of `server/src/data/news-import.json` (generated from `client-next/src/components/News/newsList.js`). It only runs while the collection is empty.
  - **Publish:** `POST /api/news/admin/publish` starts `deploy-client-next.yml` via the GitHub API, using the Fly secret `GITHUB_DEPLOY_TOKEN`: a fine-grained token for this repo only, with Actions read/write. It's limited to one publish per minute. `GET /api/news/admin/publish` shows unpublished changes and the last run. The bookkeeping lives in `site_meta/news`.
  - **Website:** `client-next/src/util/news-data.js` fetches `GET /api/news` at build time. It's used by `app/[lang]/news/page.js`, `news/[slug]/page.js` and `app/sitemap.js`.
    - The Arabic pages use Arabic text when it exists; everything else shows English.
    - Dates are formatted with `Intl` in the page's language.
    - The meta description is the excerpt, or the first 160 characters of the text.
    - **If the API is unreachable, the build fails on purpose,** so the live site keeps its news.
    - `src/components/News/newsList.js` is no longer used (kept for reference).
  - **New articles reach the site only with "Publish to website"**, or any client-next deploy.
  - **Admin panel** (`admin-dashboard/src/components/news/`, helpers in `src/util/news.js`):
    - **Visibility:** the News menu and page show for ADMIN/SUPER_ADMIN only, via `canManageNews(role)`.
    - **Page:** the list (pin, hide, delete when hidden, open on the site), the add/edit form with English/Arabic/Photos & date/Preview tabs, the one-time Import button (shown while empty), and the Publish panel, which refreshes every 20s while a build runs.
    - **Photos:** compressed in the browser (WebP, 1600px) and uploaded in batches of 15. The star marks the cover photo.
    - **Orphans:** photos uploaded and then removed before saving, or left in a cancelled form, stay in Storage.
    - **Role after login:** `Login.js` loads `check-auth` right after login so the role (and so the News menu) is known without a refresh.
- **Projects** (managed in the admin panel since projects phase 1; the website reads them at build time):
  - **Storage:** Firestore `projects`, one doc per project whose **doc id is the project number** = its web address (`/projects/7`). Fields: `name` / `city` / `description` as `{en, ar}`, `countryId`, `thumbnail`, `images[{src,alt}]`, `materials` (product ids from `materials`), `legacyMaterials` (old names without a product; can only be removed), `order` (inside its country), `hidden`.
  - **Countries:** Firestore `project_countries` (`name {en, ar}`, `order`): the groups of the Projects page and their order. A country with projects can't be deleted; an empty country isn't shown on the website.
  - **Numbers** are never reused: `site_meta/projects.lastNumber`.
  - **API:** public `GET /api/projects` returns `{countries, projects}` in page order, visible projects only, with materials resolved to `{id, name, type}` (hidden or deleted products are left out). Admin endpoints under `/api/projects/admin/*` (ADMIN/SUPER_ADMIN): list (with the product picker list), add/edit, hide, delete when hidden, move up/down, photos (`uploads/Projects/`), countries (add, rename, move, delete when empty), one-time import of `server/src/data/projects-import.json` (16 projects, 7 countries; generated from `projectList.js`, with Arabic country and city names).
  - **Admin panel** (`admin-dashboard/src/components/projects/`, helpers in `src/util/projects.js`): menu item for ADMIN/SUPER_ADMIN only (same rule as News). Projects grouped by country in page order, with arrows to move a country or a project, hide, delete when hidden, open on the site, and the one-time Import button (shown while empty). The form has English / Arabic / Country & materials (country dropdown with "+ New country", product picker grouped by category, removable old unmatched names) / Photos / Preview tabs. `CountryDialog.js` adds or renames a country.
  - **Website:** `client-next/src/util/projects-data.js` fetches `GET /api/projects` at build time (the build **fails on purpose** if it's unreachable, like news) and adds each material's product card data (Honed/Polished photo) from `getProducts()`. Used by `app/[lang]/projects/page.js` (cards only), `projects/[projectId]/page.js` (one page per number; placeholder `no-projects` page when empty) and `app/sitemap.js`. Arabic pages use the Arabic name/city/country/description when written, otherwise English. The description shows under the location and is the page's meta description (first 160 characters). The "View" button on a card is a real link. `src/components/Projects/projectList.js` is no longer used (kept for reference).
  - **Changes reach the site only with "Publish to website"** (or any client-next deploy).
- **Publish bookkeeping** is shared by news and projects (`server/src/services/site-meta.service.js`, doc `site_meta/news`). `GET/POST /api/publish` is the shared Publish endpoint; `/api/news/admin/publish` does the same. In the admin panel both pages use `components/publish/PublishPanel.js`, and photo uploads go through `uploadSitePhotos()` in `src/util/news.js`.
- **Stone details** (SEO Phase 2 Part B): Firestore `product_details`, doc id = the product's id in `materials` (kept separate so `GET /api/storage/all`, loaded in the browser, stays small). Fields: `description` `{en, ar, fr, es, de, it, ro, ko, sq, ru, ja, zh}` (en/ar edited in the panel; the other 10 are translations of the English text and are **dropped automatically when the English changes**), `otherNames[]`, `origin`/`colour` `{en, ar}`, `forms` (slabs/tiles/blocks), `thicknesses`, `sizes`, `uses` (flooring, wallCladding, exteriorCladding, staircases, windowSills, countertops, landscaping), `tech` (density, waterAbsorption, compressiveStrength, flexuralStrength; numbers or null). API: public `GET /api/storage/details` (`{productId: details}`, visible products only), `GET/PUT /api/storage/admin/details/:id` (MODERATOR+, same as editing products). Saving marks the site as changed (Publish). Deleting a product deletes its details.
- **Stone details in the admin panel:** Products page → the "Website details" button (article icon) on each row opens `components/products/ProductDetailsForm.js` (English / Arabic / Specifications & uses tabs). It warns that changing the English description drops its translations. The one-time "Import stone details" button was used on 2026-11-03 (94 stones imported) and then removed from the panel; the server endpoint `POST /api/storage/admin/details/import` (ADMIN, `server/src/data/stone-details-import.json`) still exists and never overwrites.
- **Stone details on the website:** `getProductDetailsMap()` (`src/util/product-slugs.js`) reads `GET /api/storage/details` at build time (if it fails, pages are built without details, no build failure). `productDetailsView()` in `src/util/product-seo.js` turns them into the page's language: the stone's own description (when written in that language) replaces the generated intro and becomes the meta description; "Also known as" under the H1; a Specifications box (origin, colour, forms, thicknesses, sizes, technical data); Uses chips; and the application icons are limited to the forms/uses that were set (all 7 icons when none were set). Labels: `productDetails.alsoKnownAs/specs*/usesTitle/form_*/use_*` in all 12 translation files.
- **Customers / admins / documents**: Firestore collections `customers`, `admins`, `documents`.
- **Customer accounts (login/signup/account redesigned 2026-11-11, concept "From our quarry to your port")**: pages in `client-next/src/components/Auth/` (`Login.js`, `Signup.js`, shared `Auth.css` scoped `.au`, `StonePicker.js`, `RouteMap.js`, `Journey.js`, `PasswordField.js`, `auth-util.js`) and `MyAccount/MyAccount.js`; texts in the `auth.*` section of all 12 translation files. Signup is 4 steps: account (name, email, password with the server's rules shown live) → company (company, country in the page's language via `Intl.DisplayNames`, phone, WhatsApp) → stones (optional picker) → port/address/tax ID (optional). Customers have `savedStones` (product ids, max 50) set at signup or on the account page (`PUT /api/customer/me/edit`, Joi-validated; email/phone/password can't change there). `port` is optional on the server since then. The old `LoginSignup/` folder and `MyAccount/MyAccount.css` are unused. Auth calls pass `{ quiet: true }` to axios so `src/util/client.js` doesn't also show its error pop-up (the page shows its own message).
- **Everything else is static in the repo**: page text is in `client-next/translations/*.json`. Data lists such as quarries, machinery and certificates (not news or projects any more) are JS files in `client-next/src/components/<Section>/`. Images are in `client-next/public/Assets/Media/`.
- No database or volumes on Fly. The Mongo/Prisma code in `server/` is dead.
- Firebase project ID: **`wadi-degla-app`** (bucket `wadi-degla-app.firebasestorage.app`). The owner regained console access on 2026-11-01.
- **Firebase Storage rules deny everything** (`allow read, write: if false`, set by the owner 2026-11-07): nothing uses the Firebase client SDK. The server uses the Admin SDK (ignores rules) and every photo/PDF link is a public `https://storage.googleapis.com/...` object URL (`makePublic()`), which the rules don't affect. This closed the public file listing (`firebasestorage.googleapis.com/v0/b/<bucket>/o`), which exposed every file name, invoices included.
- **Documents (invoices, packing/price lists) are private** (2026-11-07): `generate-upload-pdf` saves the PDF straight from memory to `documents/` in Storage with no public link and stores its `path` in Firestore `documents` (older docs have a public `url` instead; the path is derived from it). The admin panel opens a PDF through `GET /api/export-pdf/invoice/:id/file` (MODERATOR+, streamed by the server). At server start `makeOldDocumentsPrivate()` removes public access from every file under `documents/` once, then sets `site_meta/news.documentsPrivateAt`; delete that field to run it again.
- **Document templates** (`server/src/templates/*.hbs`, made into PDFs by Puppeteer) must not load anything from other websites: Chromium waits for every outside file, and a slow or blocked host made "Create document" fail after 60 s (fixed 2026-11-07). The logo and QR code are files in `server/src/templates/assets/` (the website's colour logo and QR code), embedded as `{{{logoSrc}}}` / `{{{qrSrc}}}` by `getEmbeddedImages()` in `pdfExport.service.js`. Add new images the same way.
- Admin passwords are bcrypt hashes in `admins`. Lost admin access: `fly ssh console -a server-withered-wildflower-1595`, then `node /app/scripts/admin-access.js list` or `node /app/scripts/admin-access.js reset-password <email>`.

## client-next structure
- There is **no** `app/layout.js`. `app/[lang]/layout.js` is the root layout for all language pages and renders `<html lang dir>` + `<body lang>` per language at build time. `app/(root)/` holds the `/` redirect page with its own small root layout.
- `src/components/RootHtml.js`: the shared `<html>`/head for both root layouts (metadata `rootMetadata`, Organization/WebSite JSON-LD, GA4). Edit site-wide head content there. Its Organization JSON-LD holds the official business details (name, address, main phone +20 10 6726 0314, email, Google Maps link, social profiles, hours Sat-Thu 9-17): they must stay identical to the Contact page, the Google Business Profile and every directory listing (SEO Phase 3 listing kit). Since 2026-11-08 its phones, emails, map link and social profiles are read from `Contact/contactData.js`, so they can't drift apart. It has `@id` `https://www.wadidegla-eg.com/#organization` (ids in `src/util/schema-ids.js`), referenced by the WebSite node (`publisher`) and by the topic pages' WebPage node (`topicBreadcrumb()` in `topic-build.js`); `legalName`, Arabic/Korean `alternateName`s, a `disambiguatingDescription` (not Wadi Degla Holding / Developments / Sporting Club), `knowsAbout`, `hasCredential` ISO 9001:2015, and the map link inside `location` (schema.org has no `hasMap` on Organization). `sameAs` starts with the Google Business Profile (`GOOGLE_PROFILE_URL` in `contactData.js`, the profile's own Share link, added 2026-11-09). The logo is `public/logo-512.png` (Google rejects SVG logos), made by `tools/make-logo-png.js` from the colour logo. Check changes with validator.schema.org (allowed in this cloud environment).
- `app/sitemap.js`: generates `/sitemap.xml` at build time (all public pages × 12 languages with hreflang, products from the live API via `src/util/product-slugs.js`, projects, news). **Add new public pages to its `STATIC_PAGES` list** (with their translation `sections`, or `topic`). `<lastmod>` is never the build time (2026-11-08): static pages get the newest git commit of their wrapper, imported component folders and own translation sections (`src/util/page-dates.js`); news the article's year-month; products and projects none (the API has no updatedAt). The Fly Docker build has no `.git` (`.dockerignore`), so the live sitemap has no `<lastmod>` for static pages until git dates are passed into that build.
- **Social previews (Open Graph / Twitter)**: every page's `generateMetadata` spreads `...buildSocial({ title, description, path, lang, image })` (`src/util/meta.js`): og:url = the page's canonical, og:locale = its language, its own title/description; stone pages use the main (Polished) photo, topic pages their hero, projects/news their thumbnail, others `/preview.webp`. New pages must do the same, or they show the root layout's homepage preview.

Home and the content pages render at build time (their text is in the static HTML for Google). ## Gotchas
- `client/` duplicates most of client-next. Edit **client-next only**.
- Product pages are generated at build time from the live API (fallback: `FALLBACK_PRODUCT_SLUGS`). If the API can't be reached, the build prints `[product-slugs] Products API unreachable…` and product pages are built **without content**: check for that line in the build log.
- Local builds: Next.js keeps build-time `fetch` results in `client-next/.next/cache/fetch-cache` between builds. After building against a different or empty API, delete that folder first. CI and Fly builds start fresh.
- In cloud sessions Node's `fetch` ignores the HTTPS proxy, so local builds can't reach the API (silent fallback). Build with `NODE_USE_ENV_PROXY=1` there. GitHub Actions and Fly builders have direct access. A product added in the admin panel only gets its own page after the next client-next deploy.
- nginx caching: `/_next/static/` (hashed build files) 1 year `immutable`; other static files (photos under `/Assets`, icons, fonts) 30 days + ETag revalidation, so a replaced photo reaches everyone within 30 days (use a new filename if it must change immediately). HTML, `sitemap.xml`, `robots.txt`: no-cache.
- Site photos: WebP quality 75, max 1600 px (banners in `Hero/` max 2000 px). Use `tools/optimize-images.js` (same settings) for new photos.
- `LangLink` has `prefetch={false}` by default: each page's data carries its language's texts (~22 KB gz), so automatic prefetching of visible links cost 160-270 KB per page view.
- Visualizer: mockup photos load on hover/touch/click of a product (never preload them all: ~36 MB). The home/exports globe (amCharts, ~300 KB) loads via `Exports/LazyGlobeChart.js` when scrolled into view.
- Components that render at build time must not touch `window`/`document`/`localStorage` during render (only in effects or event handlers), or the build fails / hydration breaks.
- Mobile counter slider (`About/CounterSection.js`) shows static numbers: CountUp inside the looping Swiper restarts or never starts (it showed "0 +").
- `server/.dockerignore` excludes `src/common`, so that folder doesn't exist in the image: never write files there (document PDFs are uploaded from memory).
- The Fly API token in cloud sessions is **read-only**: it can't deploy or change anything.
- In cloud sessions the Docker daemon isn't started by default (`dockerd &`), and Docker builds can't reach Debian mirrors through the proxy, so the server image can't be built there.
- Fly's own GitHub integration used to deploy the server and old client on **every** push to `main`, in parallel with our Actions (two releases per merge, lease conflicts). It was unlinked (Settings > "Unlink GitHub Connection") on 2026-11-01; the first attempt didn't take effect. If a merge creates two releases again, check the app's Settings > GitHub in the Fly dashboard. Ignore the "merge new files" banner.
- Release image tags: `deployment-01…` come from GitHub Actions (flyctl); `deployment-<32 hex>` came from Fly's GitHub integration.
- `nginx.conf`: the first `server` block (the non-www redirect) is the default for unknown hosts, so locally `http://localhost` redirects to the live site. For local tests, add `localhost` to the second block's `server_name` in a **copy** of the config.
- `nginx.conf`: `add_header` in a `location` drops all server-level headers, so the security headers are repeated in every location that sets its own headers. Keep the copies in sync.
- Login (`/api/auth/admin/login`, `/api/auth/customer/login`): 10 attempts per 15 minutes per IP, in memory per machine.
- Admin sessions: the JWT lasts 7 days, but `adminAuth` refuses tokens issued before the admin's `sessionsValidAfter` (ms timestamp in `admins`). `POST /api/auth/admin/logout` and `admin-access.js reset-password` set it, so logout ends that admin's sessions on **all** devices. The admin panel sends a 401 back to `/login`.
- New admins are validated (`server/src/validations/admin.validation.schema.js`): role must be `MODERATOR`, `ADMIN` or `SUPER_ADMIN` (the panel shows a dropdown) and the password must follow the login rules. Never `console.log(req.body)` on the server (it held new passwords).
- `/api/send-email`: rate limited to 5 per 15 minutes per IP (`Fly-Client-IP`), in memory per machine. It has a honeypot field `website`, and visitor HTML is reduced to `p/strong/ul/li/br` with no attributes.
- Customer auth on the website is **token-only**: the JWT is stored in `localStorage.auth_token` (raw, no quotes) and sent as `Bearer` by `src/util/client.js`. The server's auth cookie is never sent cross-site. `GlobalStateContext` only calls `check-auth` when a token exists.
- Internal links in components: use `LangLink` (never `<a href="/...">`). A bulk mechanical change across many files is done with a script, not the Edit tool, to avoid the format hook reformatting every file.
- Merging a PR that touches several app folders redeploys **each** of those apps (including the admin app; `client/` no longer deploys automatically).
- Admin dashboard: CRA treats lint warnings as errors when `CI=true` (GitHub sets it), so CI builds it with `CI=false`.
- Admin dashboard on phones (2026-11-07): below 900 px (`md`) `Layout.js` uses a slide-out menu (☰) instead of the fixed 280 px one; the theme (`src/theme.js`) makes dialogs nearly full-screen and table cells tighter on phones (<600 px); list tables hide minor columns on phones with `display: { xs: 'none', sm: 'table-cell' }` and show their text under the name. Desktop (≥900 px) must stay unchanged. Test without a real login: build with `REACT_APP_BASE_API_URL=http://api.test`, then in Playwright set `localStorage.auth_token` and answer `http://api.test/**` with sample JSON (`check-auth` returns `{username, role}`).
